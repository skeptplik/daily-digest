Anthropic has introduced Claude Ship, a set of agents that can review GitHub pull requests, push fixes, and approve the changes a team's policy allows, on Claude Team and Enterprise plans. Code Review is generally available; PR Steward and Claude Approvals are in beta.
Code Review inspects a pull request, verifies findings, and posts them; administrators pick Quick, Standard, or Deep per repository. PR Steward is designed not to approve or merge. It works on failing CI, merge conflicts, and review feedback. Anthropic recommends Manual mode first, where it runs only after someone with write access comments @claude steward. Developers can also run /ship in Claude Code to open a pull request, review it, and work through failing checks. What merges still depends on permissions and branch rules.
Claude Approvals starts when a connected repository has .claude/approvals.yml, with version: 1, on its default branch. Each rule sets path patterns and a verdict: how many human seats the change needs, and whether Claude approves, comments, or blocks. Anthropic recommends mode: observe first, where the check reports what the policy would decide and normally passes. It blocks a merge only when GitHub requires it. Omitting the mode line enforces the policy.
The author can fill a seat, so seats: 1 can mean nobody else has to look, and seats: 0 can let a bot-authored pull request merge with no person involved. Claude's approving review can satisfy a GitHub rule that requires one approval. A rule with claude: approves does not start Code Review by itself. Approvals reads the policy from the default branch, so a pull request that edits the file is judged by the rules already merged. Anthropic's starter policy asks for two people on paths under .claude/, and does not let Claude approve them. Usage is billed on tokens. It is unavailable with Zero Data Retention, a HIPAA configuration, or customer-managed encryption keys.

An agent chasing a green CI check can quietly weaken a test or patch the symptom just to make the failure go away, they said. Background pushes can also race a human review: if Steward pushes after the review, I'm no longer merging what I actually checked. They suggested locking merges to an exact head SHA.

What happens when the model that wrote the code is the one approving it, and bet that within 30 days someone shows a PR that edits the policy file getting auto-approved.
GitHub Copilot code review, Graphite's AI reviews, and OpenAI's Codex reviews comment on pull requests without replacing an approval policy. CodeRabbit can post an approving review when Automatic Approvals is on, still subject to GitHub branch rules. Teams have long used GitHub CODEOWNERS and branch rulesets for path-based human reviews. Anthropic describes Approvals as working like a smarter CODEOWNERS file.
PR Steward and Approvals remain in beta. Teams already on Code Review can add Steward and an observe-mode policy; setup is in the documentation.
