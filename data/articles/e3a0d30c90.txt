The Uno Platform team released Uno Platform 7.0, which unifies rendering on SkiaSharp 4 with an experimental WebGPU backend, adds Apple TV as a target platform and supports .NET 11 from day zero. The release also brings third-party .NET MAUI controls and Microsoft.UI.Reactor library to every target, and removes native rendering and Mac Catalyst.
Uno Platform is an open-source framework for building .NET applications with C# and WinUI XAML for Windows, Android, iOS, macOS, Linux and WebAssembly. The team describes 7.0 as its largest release, with 5,219 commits and 704 closed issues since 6.7. According to the team’s benchmarks, 7.0 is about 2x faster at the median and 5x smaller than 6.7, with some operations, such as brush creation, up to 38x faster. These figures come from the vendor and the workloads were not published in detail.
All targets now render through one pluggable pipeline. SkiaSharp 4 is the default, and Uno Platform is a co-maintainer of the library alongside the .NET team at Microsoft. On Android, Windows and Linux, Skia now renders through Vulkan by default. The WebGPU backend, available on all desktop, mobile and WebAssembly targets, is enabled by adding WebGpu to UnoFeatures and registering the backend on the host builder. It uses wgpu-native outside the browser and the browser’s own WebGPU support on WebAssembly. The team measured up to a 50% frame-rate improvement depending on the scene, and says a WebGPU-only app drops about 6 MB of uncompressed native code from WebAssembly builds. A new WebGpuCanvasElement lets applications issue their own WebGPU commands inside the UI.
Through .NET MAUI Embedding, controls from vendors such as Syncfusion, Telerik, Infragistics, DevExpress and Esri previously ran only on iOS, Android, macOS and Windows. They now work on every Uno Platform target, including the web and Linux. In the other direction, existing .NET MAUI apps can reach the browser and Linux through Uno Platform’s .NET MAUI handlers.
Microsoft.UI.Reactor, Microsoft’s declarative C# framework for WinUI with hooks such as UseState and no XAML, now runs on desktop, browser, Android and iOS. It is enabled with the Reactor UnoFeature, is in preview, and can coexist with existing XAML pages in the same visual tree. Apple TV support is added through the net10.0-tvos target framework, targets tvOS 15 and later, renders through Metal and uses the Siri Remote for focus navigation. .NET 11 is supported on every head, for example through dotnet new unoapp -tfm net11.0, while .NET 10 remains the long-term support option.
RichTextBlock and RichEditBox are now available on every platform, closing an issue opened in 2018. WinUI alignment continues with ItemsRepeater and ItemsView ported from current WinUI sources, LinedFlowLayout, the TitleBar control, multiple windows on iPad and Lottie rendering through Composition. Smaller additions include built-in input validation through INotifyDataErrorInfo, TalkBack, VoiceOver and AT-SPI screen-reader support, and the uno-devserver app command for launching and inspecting running apps from scripts and CI.
The breaking changes are:
- Native rendering is retired, although native views such as maps and video players can still be embedded.
- Uno.Sdk single-project apps are the only supported project format, with the UNOB0029 and UNOB0022 diagnostics for older projects.
- Mac Catalyst is removed, and macOS apps use the net10.0-desktop head.
- Apps target net10.0 by default, and the Windows head uses Windows App SDK 2.4. Minimum versions are iOS and tvOS 15.0, Android API 24 and Windows 10 19041.
- Libraries built against 6.x are binary-incompatible and must be rebuilt, and DependencyObject is now a single class without DependencyObjectStore.
Most apps upgrade by changing the Uno.Sdk version in global.json, following the migration guide. The team released Uno Platform Studio 3.3 alongside it.
The release follows Uno Platform 6.7 in September, which added Android TV, Android Auto and Wear OS targets, semantic styles shared by the Material and Simple themes, and damage-region repainting on Skia renderers. It also removed the WPF targets.
