AWS recently introduced Account Access Manager to centrally assign workforce users and groups to existing IAM roles across an organization, preserving custom trust policies and ABAC configurations while improving individual identity attribution and auditability.
Previously, organizations had two options for workforce access to AWS accounts: direct IAM role federation or IAM Identity Center. IAM role federation provides flexibility through custom trust policies, tags, and paths, but requires configuring identity providers and managing access independently in each account. IAM Identity Center provides centralized federation and provisioning through permission sets, but can be restrictive when teams need account-specific roles or permissions. Moumita Saha, senior security identity specialist solutions architect at AWS, Blake Franzen, senior security solutions architect at AWS, and Omar Zoma, principal security solutions architect at AWS, write:
Account access manager removes the trade-offs. It’s built for customers who want the single federation point and identity-propagation benefits of IAM Identity Center together with the flexibility of IAM roles.
Source: AWS blog
Account Access Manager combines the flexibility of IAM roles, including support for custom trust policies and role paths, with the centralized workforce federation capabilities of IAM Identity Center and user-level auditability. AWS recommends enabling it in the organization's management account, in the same Region as IAM Identity Center, and automating trust policy updates in role-creation pipelines.
Account Access Manager can operate independently or alongside existing IAM Identity Center permission sets, using the same users and groups. It propagates individual user identities into IAM role sessions, enabling actions to be attributed to specific users even when they share the same role. The service also introduces a dedicated account-access API namespace, with separate IAM permissions and CloudTrail events for auditing access assignments and related operations. Corey Quinn, chief cloud economist at The Duckbill Group, writes:
IAM, SSO, Identity Center, permission sets, and now this thing that can work "alone or alongside" the others. There’s no solution to fragmentation quite like adding more options.
At launch, AWS announced integrations with several partners, including Okta, Ping Identity, Cisco Duo, BeyondTrust, Britive, Sonrai Security, Apono, Lumos, C1.ai, and Pulumi. Saha, Franzen, and Zoma add:
Account access manager also integrates with leading infrastructure-as-code (IaC) partners, so teams can define and manage access assignments declaratively alongside the rest of their AWS infrastructure. Pulumi enables customers to codify account access manager role assignments as part of their existing provisioning workflows, bringing repeatable, version-controlled automation to workforce access at scale.
The team has released the open source AAM Migration Tool, that automates migration from IAM Identity Center permission sets or SAML-based IAM federation to Account Access Manager. The project supports identity and policy discovery, migration planning, IAM role creation, entitlement mapping, and CloudFormation template generation through a browser-based interface or CLI.
IAM Identity Center CLI commands, such as aws sso configure, are not supported for Account Access Manager assignments and should instead be replaced by aws login. The new feature is available at no additional cost in all commercial regions.
