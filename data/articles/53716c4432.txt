Microsoft is warning customers that a security vulnerability in Azure API Management (APIM) Classic tiers was exploited to steal stored API credentials, with Norwegian authorities linking the flaw to cyberattacks against energy companies.
Azure API Management is a cloud service that lets organizations publish, secure, monitor, and manage APIs that connect applications, services, and data.
In an Azure Service Health security advisory (Tracking ID: MZK9-GH0) sent to customers and shared with BleepingComputer, Microsoft said it identified the vulnerability on November 18, 2026, and deployed a mitigation the following day.
"Our investigation found that customers were exposed and an unauthorized party could have used the issue to access secrets stored in Azure API Management Classic instances before Microsoft identified the security issue," Microsoft said in the advisory.
Microsoft told BleepingComputer that the vulnerability impacted the Developer, Basic, Standard, and Premium tiers of Azure API Management (APIM) Classic, but that the Consumption tier of APIM Classic and all APIM v2 tiers were not affected.
According to Microsoft, the vulnerability allowed unauthorized access to certain management functionality when APIM Classic instances were not configured according to recommended security best practices.
This access could have allowed attackers to perform administrative operations, including accessing secrets stored in the service.
Microsoft said the following information may have been exposed:
- Secrets stored in Named Values
- Client secrets associated with identity providers
- Client secrets associated with OpenID Connect providers
- Subscription keys
- Tokens used to call direct management APIs
These credentials could potentially allow attackers to access additional applications, services, or backend systems, depending on their permissions.
Microsoft said it closed the unauthorized access path on November 19 and rotated Microsoft-controlled keys and credentials where appropriate.
However, the company warned that its remediation would not invalidate customer credentials that may have been compromised before the fix was deployed.
"This remediation blocks the unauthorized management-plane access path that could allow an actor to perform administrative operations, including secrets management, against Azure API Management services," Microsoft warned.
"However, it does not automatically invalidate credentials that may have been accessed before the fix was deployed."
The vulnerability affects Azure API Management Classic tiers, while Microsoft said APIM v2 tiers are not impacted.
Microsoft urged affected customers to immediately rotate potentially exposed credentials, investigate suspicious activity in systems accessible through those credentials, and review available logs for signs of unauthorized access.
In a Reddit post, an administrator claimed their organization discovered the vulnerability after detecting unauthorized access to Azure Key Vault using a valid administrator token.
"Our company has been fighting this for days, after discovering that someone logged into our keyvaults using a valid administrator token and not following the normal access pattern," the administrator claimed.
The administrator alleged that attackers exploited a zero-day authentication bypass in a deprecated legacy API to gain access to a privileged system account on APIM instances.
According to the administrator, the legacy API did not generate logs that customers could use to detect the unauthorized access. They also alleged that Microsoft initially attributed the suspicious activity to leaked customer credentials before deploying a global fix.
BleepingComputer has not independently verified these allegations.
The vulnerability has also been linked to attacks affecting Norwegian organizations, including energy companies Equinor and Skagerak Energi.
In a security advisory, Norway's National Security Authority (NSM) said an unknown threat actor targeted access tokens, secrets, and named values stored in Azure API Management.
The agency said Norway's energy sector first discovered the vulnerability and that organizations in other countries and industries were also affected.
Equinor disclosed an ongoing cyberattack on November 17, a day before Microsoft says it identified the APIM vulnerability. The company later announced that it had stopped the attack and found no indication that data had been stolen or altered.
Skagerak Energi also reported an attempted cyberattack but said it had no impact on its operations and no evidence that information was compromised.
While Microsoft says it deployed a remediation on November 19 that required no customer action, NSM's advisory warns organizations to verify that their APIM instances have received the security update.
The agency warns that instances running below specific runtime versions remain vulnerable and advises customers to contact their "service provider" if they have not received the update.
In a statement to BleepingComputer, Microsoft confirmed that its November 19 remediation was fully deployed to Microsoft-hosted API Management instances and required no customer action.
However, Microsoft did not clarify why Norway's NSM continued advising customers to check their APIM runtime versions and warning that instances below certain versions remained vulnerable.
Cloud security researcher Anders Kristiansen shared threat-hunting queries to help organizations investigate potential exploitation and identify credentials stored in their APIM instances.
This Azure API Management incident comes just days after Microsoft confirmed another security breach involving its Entra Connect Health service, where attackers exploited a vulnerability to steal tenant configuration information and administrator email addresses.
