Threat actors are chaining exploits for the PHP2Shell and Fragnesia vulnerabilities to target Palo Alto Networks devices with management interfaces exposed to the internet.
PHP2Shell is the name for two critical PHP vulnerabilities tracked as CVE-2026-109618 and CVE-2026-109619, which allow unauthenticated attackers to run code remotely with the privileges of the PHP web worker.
The Fragnesia vulnerability, identified as CVE-2026-46300, is a Linux kernel vulnerability in the XFRM ESP-in-TCP subsystem that lets a local attacker with low-privileges to escalate permissions to root level.
An alert from CISA on October 28 warned that both security issues were being chained in attacks to deploy PHP webshells on vulnerable systems and execute commands as root.
Around the same time, Dream Security researchers reported observing a campaign using the same chain, targeting servers in the United States, Japan, Taiwan, and South Korea, including a U.S. government affiliate.
Palo Alto Networks has confirmed in an advisory today that such attacks also target firewalls running PAN-OS.
“Exploitation of CVE-2026-46300 has been observed targeting the Palo Alto Networks management interface exposed to the internet,” reads the security bulletin.
The networking company says that all exploitation activity it observed involved PAN-OS devices that exposed their management interface to the public internet, which goes against its recommended ‘best practices.’
Palo Alto Networks did not provide any technical details about the chaining of the PHP2Shell vulnerabilities, but noted that this is the only known way to exploit Fragnesia, and they are not aware of another exploitation pathway for the flaw.
The company has released fixes for Fragnesia for PAN-OS 10.2, 11.1, 11.2, 12.1, and 12.2, with the exact patch-carrying build varying by release.
Given that the two flaws are exploited together, administrators who applied updates that addressed the PHP2Shell flaw should be safe from these attacks.
In addition to applying the security updates, Palo Alto Networks also recommends that those who need to keep a remote management interface available restrict access to trusted internal IP addresses.
