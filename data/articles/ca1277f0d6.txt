Bedrock Data enhances AI agent governance with intent-aware DLP
Bedrock Data has announced that Agent DLP, its runtime data loss prevention for AI agents, now infers a user’s intent (the business purpose behind the task) and evaluates the agent’s behavior (the sum of its actions across every tool and LLM call) against that intent and the organization’s policy.
By weighing both intent and behavior, Agent DLP lets employees keep working with AI agents while sensitive data stays protected. Agent DLP adds support for off-the-shelf AI tools employees and developers use, including AI assistants such as Claude, Claude Cowork and ChatGPT; coding agents such as Claude Code, Codex and Snowflake Cortex Code; data platform agents such as Snowflake Cortex; and AI gateways such as Bifrost.
According to Forrester, “Governing AI agents starts with controlling intent and authority, not models or tools. Agentic systems interpret goals, make decisions, and act across systems. Governance must therefore define and monitor whom an agent is allowed to act for, under what authority, and within which bounds.”
Enterprises are putting agents to work across development, customer support and business processes. In EY’s 2026 survey of senior AI executives at U.S. companies with at least $1 billion in revenue, 85% of executives whose organizations use agentic AI said some of their systems execute actions without real-time human involvement.
Agents are goal-oriented and take whatever actions reach the outcome a user asks for, even risky ones, such as changing security settings to get around a block, saving sensitive files to unsecured locations or sending data to unapproved MCP servers. Identity and access controls decide what an agent can access, not what it does with that access.
“Most enterprises have more agents than they think, and like most new technology, developers got there first,” said Bruno Kurtic, CEO of Bedrock Data.
“Tools like Claude Code Enterprise put agents in the hands of developers who already have broad access to production systems, credentials and customer data. In our early deployments, the riskiest activity often matched no existing policy at all. Seeing what those agents do tells a security team which policies to write first and which data to clean up, so they can enforce where the risk is real and let the rest of the work run.”
Intent, behavior and policy define how Agent DLP governs AI agents
Agent DLP looks at what an agent does: the actions it takes, the data it touches, and the MCP servers and tools it calls. It evaluates this behavior alongside the inferred intent, the business purpose the user set out to accomplish. Authorized work continues uninterrupted. When that behavior puts sensitive data at risk, Agent DLP responds according to policy by alerting the security team, masking the sensitive data or blocking the action.
“CISOs don’t want a tool that blocks authorized work, but they also don’t want policies that miss exposure,” said Sanjay Srivastava, VP of Product at Bedrock Data. “Agent DLP reads why the user asked, sees what the agent does with the data and applies the organization’s policy to both, so authorized work proceeds and exposure is stopped.”
Agent DLP judges each action in light of the user’s intent and the actions that came before it, then reviews the session as a whole, so it catches individually allowed actions that add up to exposure, with minimal latency at runtime. It plugs in wherever agents act: as a hook in tools such as Claude Code and Codex, at gateways such as LiteLLM and Bifrost, and in agent runtimes such as Amazon Bedrock AgentCore and NVIDIA OpenShell.
Agent DLP also inventories the agents in use and the tools, MCP servers and identities each relies on, and keeps a full audit trail of every action for regulatory review.
Security teams write policies in natural language to describe what agents may do. Agent DLP enforces them against the same classifications Bedrock Data uses for data security posture management (DSPM), covering structured and unstructured sensitive data across on-premises, SaaS and infrastructure platforms, so a policy means the same thing for stored data and for data an agent is using.
Sensitive data includes regulated and business-critical categories such as PII, PHI, payment card data, credentials and secrets, financial records, material nonpublic information (MNPI) and proprietary source code or IP, plus any category a customer defines.
“Home service pros trust us to run their businesses, and that trust extends to the homeowners they serve,” said Nate Burford, Housecall Pro SVP and CIO. “As we put AI to work across our teams, Bedrock Data’s Agent DLP gives us visibility into how our agents handle customer data, so we can move fast and keep it governed.”
For example, Agent DLP can block an agent from downloading regulated PII or sending it to Slack, email or another MCP server. It can also detect a toxic data combination, such as a name, a date of birth and a medical diagnosis, whether it appears in one action or builds up across a session, and mask one element so the full combination never appears in plain view.
A global investor in enterprise technology and a leading advocate for agentic AI uses Agent DLP to govern how agents work with sensitive data across its own teams. According to the CISO at this global private equity firm, “We put agentic AI to work in our own business, not just in what we invest in, and our people use agents every day on sensitive information. Agent DLP understands what each agent is doing with our data and why, so our teams can move fast while meeting the regulatory and contractual obligations we hold ourselves to.”
