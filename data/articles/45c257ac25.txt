Threat actors are exploiting an unpatched vulnerability in the open source anti-CSRF library Idunno AntiCsrf for remote code execution (RCE), security researchers warn.
AntiCsrf is a legacy ASP.NET module for WebForms applications that has no active maintainer and is no longer actively supported. The most recent version, 0.9.1 Beta, was released in December 2008.
Tracked as CVE-2026-131914 (CVSS score of 9.3), the exploited security defect is described as an insecure deserialization bug in the processing of HTTP POST requests to ASP.NET WebForms endpoints.
“Exploitation requires only a single HTTP POST request with no prior authentication or valid CSRF token. Active exploitation in the wild has been observed,” Google Cloud’s Mandiant warned on November 18.
The flaw allows an attacker to supply any non-empty value in the CSRF cookie along with a Base64-encoded gadget chain to gain RCE in the context of the IIS worker process, Mandiant notes.
According to preemptive cybersecurity firm WatchTowr, the issue exists because AntiCsrf does not perform sufficient checks on data from incoming form submissions before reconstructing it into program objects.
“The vulnerable check runs before the application’s own page logic, so it can affect many pages on an affected site, not just ones that use a login form. A successful attack gives the attacker control over the process that runs the website, which can lead to full compromise of the server,” WatchTowr says.
On Tuesday, the US cybersecurity agency CISA added CVE-2026-131914 to its Known Exploited Vulnerabilities (KEV) list, urging federal agencies to address it within three days.
As no official patch is available for the vulnerability, all organizations relying on the 18-year-old AntiCsrf to validate anti-CSRF tokens on form submissions should immediately discontinue the module and transition to an actively supported solution.
“WatchTowr Intel detected exploit probes across our honeypots that used creative .NET compiled gadget payloads to confirm if a given system is vulnerable. We validated the exploit and confirmed that, if the host was vulnerable, the server would be tricked into redirecting to a unique URL that would discreetly confirm control of the web server to the attacker,” WatchTowr principal threat intelligence specialist Yordan Ganchev told SecurityWeek.
“There is no patch, and likely there won’t be one. Defenders should audit ASP.NET products to identify ones packaging the Idunno.AntiCSRF library and review their audit logs for signs of exploitation. Where possible, the library should be replaced in affected applications. Where that’s not possible, apply WAF rules until alternative workarounds are identified,” Ganchev added.
