GL.iNet has confirmed that hackers exploited a vulnerability in its cloud remote management services to install custom malware on customers' routers and KVM devices, with some affected users reporting backdoors and reverse shells giving remote access to infected devices.
GL.iNet manufactures networking equipment, including home and travel routers, as well as KVM devices that allow users to access and control computers remotely.
Its GoodCloud platform allows customers to remotely manage supported devices, including accessing and controlling computers and servers connected to its KVM products.
In a security advisory published on November 20, GL.iNet confirmed that an unauthorized party exploited a vulnerability in its cloud remote management services to access devices and install malicious software.
"The attack path has been blocked. We fixed the cloud vulnerability and blocked the access used in this incident," the company said.
"Devices can no longer be newly infected through this attack path. These measures do not remove malware from devices that were already infected."
GL.iNet has not disclosed how the attackers exploited its cloud platform, how many customers were impacted, or whether information was stolen from compromised devices.
The company is also investigating whether computers connected to infected KVM devices were compromised.
GL.iNet recommends that customers check their devices for signs of infection and install the latest security firmware, even if no malware is detected.
The company's initial instructions told customers to look for a process running as crond -i /tmp/.log, which GL.iNet said was an indicator of compromise.
While the cloud vulnerability has been fixed, GL.iNet says stable firmware updates containing additional security fixes for both routers and KVM devices are scheduled for release on November 22, 2026.
For KVM devices, customers can follow the company's firmware upgrade guidance, which recommends version 1.10.3 or later for the RM10, RM1, RM1V2, RM1PE, and RM4PE, version 1.10.3 beta or later for the RM10RC, and version 1.8.7 or later for the RMQ1.
Router owners should install the latest security firmware for their specific model as soon as it becomes available.
However, GL.iNet forum members warn that the company's detection instructions may not identify all compromised devices, including those infected with other backdoors or running reverse shells.
GL.iNet has linked to a community-developed detection and cleanup tool as part of the company's official support instructions for routers and KVM devices.
The scanner performs additional checks for known malware files, suspicious processes, modified system utilities, and configuration files modified for persistence. It can also collect forensic evidence and optionally remove known malware components.
The project's developers warn that the scanner cannot detect every infection and that compromised devices may require reinstalling firmware without retaining existing settings, as malicious files stored in configuration directories could survive an ordinary firmware upgrade.
Customers who suspect their devices were compromised should preserve evidence before resetting them, avoid restoring potentially infected configurations, and rotate credentials and access keys that may have been exposed.
GL.iNet also asked customers who run the scanner to upload the anonymous report when prompted so the developers can determine the number and types of devices impacted.
For KVM users, the malware may have allowed access to the computers controlled by the KVM, so those devices should also be analyzed for potential compromise.
Malware and reverse shells discovered
Following the disclosure, GL.iNet customers and security researchers shared evidence of custom malware infections designed specifically for GL.iNET devices, as well as root-level reverse shells that connected compromised routers to the IP address 170.39.226[.]219.
The reverse shells used the Linux nc utility to create outbound connections, allowing remote attackers to execute commands on infected devices.
Researchers at RemoteToHome Consulting also identified a potential command injection vulnerability in GL.iNet's GoodCloud client involving a handler used for AstroWarp/SD-WAN functionality.
According to the researchers, the handler passes cloud-supplied values into shell commands executed with root privileges without properly validating them.
However, GL.iNet has not confirmed that this particular vulnerability was used in the attacks.
RemoteToHome says it analyzed 183 routers it owns or manages and found suspicious activity on 152, including 24 with root-level reverse shells, 47 with an older persistent backdoor, and 81 showing evidence that attacker-supplied commands had executed.
The researchers note that their findings may not be the same as the other GL.iNet customers and that the older backdoor infections may not be linked to the November attacks.
In a separate forum report, the owner of a compromised GL-RM1 KVM shared network logs showing it downloading a malicious ni.sh script and additional executable payloads from 66.245.219[.]252 on November 19.
The owner also reported that the device began communicating with approximately 1,800 residential IP addresses daily and repeatedly contacted the TRON blockchain API, exhibiting activity suggestive of a peer-to-peer network.
However, the purpose of these connections is unclear, and there is no confirmation that the compromised devices were being used as residential proxies or were part of a larger botnet.
BleepingComputer examined a copy of the malicious ni.sh script [VirusTotal] and found that it contains code specifically tailored to GL.iNet routers and KVM devices.
The script recognizes numerous GL.iNet device models and downloads malicious executables named gl-helper and gb from hardcoded servers.
It also establishes persistence through startup scripts and scheduled tasks, allowing the malware to restart after a reboot or if its processes are terminated.
The installer includes functionality to disguise the malicious process as crond -i /tmp/.log, matching the IOC published by GL.iNet.
An interesting feature is replacing the legitimate netstat utility with a modified shell script that filters out connections to 66.245.219[.]252, potentially hiding the malware's communications from administrators examining network connections.
The installer also contains functionality to install SSH public keys for remote access, modify file timestamps, and periodically contact a remote server to retrieve and execute commands.
The attacker's infrastructure includes two IP addresses, 66.245.219[.]252 and 65.20.71[.]131, which match the IP addresses seen in the compromised KVM owner's logs.
The script also contains Chinese-language developer comments describing its persistence mechanisms, reporting functionality, and interactions with GL.iNet's cloud management software, indicating a Chinese-speaking individual may have written it.
BleepingComputer also examined a separate malicious Lua payload recovered from a GL-MT2500 router.
The payload was launched through a modified urandom_seed startup script and included functionality to collect device information, contact remote servers, and download and execute additional programs.
Some of the malicious files recovered from GL.iNet devices had timestamps dating to December 2025, suggesting that some devices may have been compromised for months. However, it is unclear whether these infections involved the same threat actors or were related to the November 20 attacks.
GL.iNet says it continues to investigate the incident and plans to notify identified affected customers using the email addresses associated with their cloud accounts.
