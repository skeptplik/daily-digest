“Give me the top five, sorted by impact.” People ask AI agents for this all the time, whether it’s a backlog or a pile of growth ideas. Yet “impact” is one of the vaguest words in the language. It could mean how many users benefit, how much money comes in or how much you get for the effort. Hardly anyone says which, so we suspected the order agents come back with is just vibes. It looks plausible, but there’s nothing behind it.
We were wrong, though not in a reassuring way. Across 1,500 runs with four models, agents ranked the same list in nearly the same order every time, and different models largely agreed with each other. Our prompt never said what impact meant, so the agents picked a definition themselves, and which one depended on the subject: users reached for a developer-tool backlog, revenue for an online shop and severity for security work. When every item came with a dollar figure, “impact” meant the biggest dollar figure, every time.
Three kinds of vibes
When you ask an agent to sort a list by impact, the order you get back can be vibes in three ways, and each one needs to be fixed in a different way.
Eight items, ranked over and over
If we let the agent come up with its own ideas, we’d be testing two things at once: which ideas it picks and how it ranks them. So we gave it a fixed list of eight items to rank. The first list was a backlog for devkit, a made-up open-source CLI with a paid Team tier:
I maintain devkit, an open-source CLI for scaffolding and deploying serverless apps.
The core is free; a paid Team tier adds collaboration features.
Here's our backlog:
- win-paths: Fix the crash on Windows when the project path contains spaces
- sso: Add SSO/SAML login to the Team tier
- quickstart: Rewrite the getting-started docs and add a 5-minute quickstart
- deploy-speed: Cut `devkit deploy` cold start from 40s to 10s
- ...
Sort these by impact, most impactful first.
Every reply had to end with a RANKING: line listing all eight items, so we could compare orders automatically. Each list came in two versions. One had titles only, the way people usually paste a list into a chat. The other added data to each item, like “hits ~15% of users; est. 1 day”. Then we asked for the ranking in several ways:
Claude Sonnet 5.5, Claude Haiku 5.5, GPT-6.1 Sol and GPT-6 Luna ranked the backlog 15 times per prompt. We ran everything in Vally, Microsoft’s evaluation tool for AI agents, with the GitHub Copilot SDK as the agent.
The first round said “impact means reach”
On the backlog, the “sort by impact” ranking came closest to sorting by users reached. When the agents explained their ranking, most said they’d ranked by reach or by a mix that included it. Impact meant reach, apparently.
One domain is one data point, so we added two more, and this time we wrote down beforehand what would count as a result. The shop domain was a list of growth initiatives for Northbean, a small online coffee roaster. The risk domain was a list of security improvements for Ledgerly, a B2B invoicing SaaS. In the version with data, every item now had three numbers: how many people it reaches, how much money it’s worth and how many days it takes.
- cart-email: Send an abandoned-cart reminder email
  (reaches ~8,000 people/month; est. +$40k/yr revenue; est. 1 day)
- microlot-club: Launch a $45/month limited-microlot club for top customers
  (reaches ~150 people/month; est. +$70k/yr revenue; est. 2 days)
We picked the numbers so that sorting by reach, by money and by effort gave three completely unrelated orders. That way, we could tell which number the agents followed. We also had Claude Haiku 5.5 read every answer and note what the agent said it had ranked by. Claude Sonnet 5.5 and GPT-6.1 Sol ran both new domains, 15 times per prompt.
Ask again and you get the same order
Pick any two items from a list, and two runs of the same prompt put them in the same order 86% to 100% of the time, depending on the model and the list. That’s about as consistent as when we spelled out what impact meant. Different models agreed on 77% to 93% of pairs, and on 87% to 100% once the list had data.
An item’s position in the input had almost nothing to do with its rank, and reversing the list changed the full ranking only slightly. With titles only, 64% to 100% of runs picked the same #1 item. The backlog was the only list where reversing it changed the top pick. Claude Sonnet 5.5, for example, put the quickstart first in the original order and the Windows crash fix first in reverse. When agents came up with five ideas and then sorted them, the sorted order had little to do with the order they’d thought of them in, and no run handed the list back unchanged.
The hidden default depends on the domain
So what were the agents ranking by? With titles only, it depended on what the list was about. Reach, our answer from the first round, only held for the developer-tool backlog.
On the security list, the agents ranked by how bad each risk was, and enforcing hardware-key MFA for all employees came first in every run for both models. Of our three definitions, losses avoided came closest, but the agents talked about severity, which none of our definitions covered.
With dollar figures, impact meant the biggest dollar figure
When every item stated reach, money and effort, Claude Sonnet 5.5 and GPT-6.1 Sol sorted by the money column on both the shop and the security list. In every run, the ranking matched the money order exactly and had nothing to do with the reach order. The abandoned-cart email reached more than 50 times as many people as the microlot club and took half the time, and the agents ranked the microlot club higher anyway, because it was worth $70k instead of $40k.
Asking the agent to define impact didn’t help
On paper, the obvious fix is to make the agent say what it means by impact before it ranks anything. In practice, it didn’t make the rankings any more consistent, and for three of the four models, it made them less so.
What we’d test next
The first thing we’d test is whether people do any better. Give the same lists to product managers and engineers, ask them to sort by impact, and compare how often they agree with each other and with themselves a week later. If people pick different definitions too, the problem is the request itself, and you’d need to define impact no matter who does the ranking.
We’d also widen the lists. We tested three domains with one list of eight items each, all of them business decisions. A list of twenty items, or one outside business entirely, like which research papers to read first, would show whether agents still settle on one definition per domain.
What to do when you ask for a ranking
If you ask an agent to sort anything by impact, or by a word that’s just as vague, like priority or importance, say what you mean by it, such as expected revenue or value per day of effort. If you don’t, the agent picks one for you, and it might not be the one you had in mind. Asking the agent to define impact first sounds rigorous, but you still get a definition the agent chose, and in our runs the rankings got less consistent. If you’re not sure which definition fits, ask for several rankings, one per definition, and compare them. Items that rank high on every definition are the safe bets, and the ones that move are where the real decision is.
Watch what data you put in the list, because the numbers you add define “impact” as much as the words do. If your items carry dollar figures, expect the agent to sort by them and ignore everything else you included.
If you build skills, prompts or agents that rank things for people, like triaging incoming issues or summarizing review findings, put the definition in the instructions. When a word is ambiguous, an agent quietly picks a definition and sticks to it. Like the preferences people attribute to models, that definition comes from the context, such as the subject of the list or the numbers in it.
If you evaluate agents that rank, add the word itself to your list of hidden variables. The same prompt tests one definition on a shop’s growth ideas and a different one on a security backlog.
So, is “sort by impact” just vibes?
“Sort by impact” turned out far more consistent than we expected. Agents gave nearly the same ranking run after run and mostly agreed with each other, whatever order the list came in.
It’s vibes in a subtler way. The agent ranks by a definition it picks from the subject of the list: reach for a developer tool, revenue for a shop, severity for security and the biggest dollar figure whenever there is one. Because the ranking comes back the same every time and sounds well-reasoned, it’s easy to mistake for a judgment you agreed with.
