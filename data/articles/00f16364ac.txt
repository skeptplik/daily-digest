Microsoft has confirmed that customers may experience authentication issues after installing November security updates that address a high-severity remote code execution vulnerability.
Tracked as CVE-2026-118737, this security flaw was found in the Windows Remote Procedure Call Runtime and stems from a timing-dependent authentication weakness that unauthenticated attackers can exploit to remotely execute code without user interaction on unpatched systems.
Microsoft says the November security updates represent the first phase of NTLM message-signing improvements, which reduce exposure to relay attacks by ensuring authenticated NTLM sessions always establish a cryptographic session key and negotiate real message signing.
However, as Microsoft explained in an updated support document, the new security improvements introduced to address this vulnerability may also cause authentication failures on patched devices.
"Microsoft is aware of compatibility issues affecting some third-party apps and devices, including authentication proxy servers, single sign-on (SSO) solutions, and application packaging solutions that use NTLM authentication," it said.
"This issue can occur when such a proxy device does not correctly implement the NTLM protocol. For example, an affected device might set the NTLMSSP_NEGOTIATE_TARGET_INFO flag in its CHALLENGE_MESSAGE but provide an empty or incomplete TargetInfo field."
While a fix is not yet available, Microsoft said affected apps and devices return an NTLMSSP_CHALLENGE message with an empty "Target Info List" in network trace signatures or Target Machine fields with "Not Found" values in event logs.
As a temporary workaround, the company advised customers to go through the following procedure on affected systems:
- Set the ClientAllowUnsignedNtlm REG_DWORD registry value under HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0 to 1 (the value used for clients that do not offer SIGN)
- Check whether the affected device or application supports a configuration that uses Kerberos authentication or whether the vendor provides a software or firmware update compatible with the NTLM signing requirements introduced by CVE-2026-118737.
- If neither option is available, contact the device or software vendor to request an update that complies with the NTLM protocol requirements described in 3.1.5.1.2 Client Receives a CHALLENGE_MESSAGE from the Server.
However, Microsoft said the ClientAllowUnsignedNtlm registry setting is a short-term solution and may be removed in the future.
"Updating the affected product or using a compatible authentication configuration is the recommended long-term resolution," it noted.
Since it addressed installation issues affecting the November 2026 cumulative updates, Microsoft has also confirmed that this month's security updates are causing Windows activation failures and SQL Server performance issues.
The company is also investigating a known issue that may break printing documents with complex formatting for customers who have installed the latest Windows updates.
