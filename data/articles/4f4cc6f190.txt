Apache has released security updates to address a critical Roller flaw that threat actors are exploiting to gain code execution on vulnerable servers.
Apache Roller is an open-source, Java-based group-blogging server with a much smaller market share than modern content management systems and blogging platforms.
However, while this is a niche product, Apache has flagged the flaw (tracked as CVE-2026-129448) as actively exploited in the wild.
Apache has not yet provided details about these ongoing attacks, including who is responsible and how many servers have already been compromised.
"Deserialization of Untrusted Data in Apache Roller versions 4.0.0 through 6.1.4 allows an unauthenticated remote attacker to execute arbitrary code. The XML-RPC endpoint accepts vendor extension types and deserializes them before authenticating the requester," Apache explained in a Tuesday security advisory.
"This is the same vulnerability as CVE-2026-82384, which listed only Apache Roller 6.1.5 as affected. This issue is being actively exploited."
To block ongoing attacks, Roller users should immediately upgrade to Apache Roller 6.1.6 or later, which disables the extension types and rejects malicious XML-RPC requests after turning off the XML-RPC feature.
Admins who can't immediately upgrade can also temporarily mitigate CVE-2026-129448 by setting "enabledForExtensions" to "false" in WEB-INF/web.xml, removing the "/roller-services/xmlrpc" servlet mapping, and restarting Roller.
According to Apache, disabling XML-RPC in the administration user interface is not enough to block attacks because older versions deserialize the request before checking whether that setting is toggled on.
In April, the US Cybersecurity and Infrastructure Security Agency (CISA) also flagged a 13-year-old Apache ActiveMQ vulnerability (CVE-2026-34197) as exploited in attacks and ordered federal agencies to secure their systems within two weeks.
More recently, earlier this month, Apache fixed a critical vulnerability in the HTTP/2 module of Apache HTTP Server that an unauthenticated attacker could exploit to gain remote code execution on unpatched servers.
Since November 2021, CISA has added 41 Apache flaws to its catalog of vulnerabilities exploited in the wild, eight of them also abused by ransomware gangs.
