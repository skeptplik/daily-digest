OpenAI and Cisco on Monday unveiled Shirudo, an open source security platform that uses AI agents to prevent the exploitation of vulnerabilities in Linux systems and applications.
The project is an AI-focused rewrite of Cisco-owned Isovalent’s Tetragon runtime security platform. Tetragon was open-sourced in 2022, and it also powers Cisco’s Live Protect vulnerability mitigation technology.
Shirudo is designed to help defenders address the challenges introduced by AI-accelerated vulnerability discovery and exploitation, which is increasing pressure on organizations to deploy patches quickly.
The tool leverages eBPF technology to modify Linux kernel behavior without restarting the OS.
According to Cisco and OpenAI, agents can analyze vulnerability information, generate so-called ‘shields’ to prevent exploitation, and test their effectiveness without disrupting important services. Security teams still retain control over which shields are deployed.
Protections are digitally signed and verified before deployment, with mechanisms designed to prevent even attackers with root privileges from disabling kernel-level enforcement.
In a controlled test targeting the recent Java4Shell vulnerability, a shield generated using OpenAI’s Codex blocked an exploitation attempt targeting an Elasticsearch instance without requiring a restart.
Shirudo is currently in pre-release development and not ready for production use. The tool requires specific Linux kernel capabilities, additional kernel patches, and TPM 2.0.
OpenAI and Cisco hope that down the line Shirudo shields can be distributed alongside vulnerability disclosures to give organizations temporary protection until they can install permanent patches.
Amiram Shachar, CEO and co-founder of cloud security firm Upwind, commented, “Writing the most sensitive kernel code on the fly and deploying it straight to runtime is a very risky concept. I love the idea, but doing it with open source is very risky.”
“There are countless Linux versions and distributions this has to work across. It needs to be tested, packaged and automated before anyone should trust it in production,” Shachar added.
