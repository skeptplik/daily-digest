Two critical vulnerabilities in Apache software are being exploited in attacks, and CISA added one of them to its Known Exploited Vulnerabilities (KEV) catalog on Wednesday.
Apache Axis vulnerability exploited in attacks
CVE-2026-90436, disclosed on November 6, is an unsafe reflection vulnerability in Apache Axis 1.x, an end-of-life Java-based SOAP implementation. The flaw has a CVSS score of 9.8 and can allow unauthenticated attackers to execute arbitrary code on vulnerable systems.
Rapid7 detected exploitation on November 13 in a customer environment running Atlassian Confluence Data Center. The attacker executed hundreds of commands, accessed Confluence’s database using the application’s credentials, and searched for sensitive information.
Within four hours of the initial exploitation, the attacker had obtained a service account credential and was querying a production cloud data warehouse. Roughly twelve hours after the first exploit request, the attacker signed in to Microsoft 365 using an integration service account.
Rapid7 also cited N-able’s report of attacks against N-central involving a vulnerability strongly correlated with CVE-2026-90436. Both Confluence and N-central require non-default configurations to be vulnerable.
Separately, Previdian reported detecting 50 exploitation attempts from 14 IP addresses between November 12 and 19. Its sensor data does not establish whether those attempts succeeded.
Apache does not plan to release a fixed Axis 1.x version and recommends migrating to another SOAP engine or applying its published patch.
Confluence Data Center users can upgrade to version 9.2.28 or an unaffected 10.x release. N-central 2026.4 HF3 disables the Legacy API functionality that exposes the vulnerable Axis component.
CISA has added CVE-2026-90436 to its KEV catalog, instructing federal agencies to address it by November 21.
Apache Roller vulnerability also exploited
Apache has also confirmed active exploitation of CVE-2026-129448, a CVSS 9.8 vulnerability affecting versions 4.0.0 through 6.1.4 of its Java-based blogging platform Roller. The flaw allows unauthenticated remote code execution.
“This issue is being actively exploited,” Apache said in its November 17 advisory, without providing further information about the attacks.
The vulnerability stems from unsafe deserialization in Roller’s XML-RPC interface, which processes malicious data before authentication. Disabling XML-RPC through the application’s administration interface does not prevent exploitation.
Apache initially disclosed the same underlying vulnerability in September as CVE-2026-82384.
“This is the same vulnerability as CVE-2026-82384, which listed only Apache Roller 6.1.5 as affected,” Apache explained.
The flaw was fixed in Roller 6.1.6. Apache recommends upgrading to that version or later. Version 6.1.7, released on November 11, addresses another 15 vulnerabilities.
