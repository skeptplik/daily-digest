In this episode, Edoardo Vacchi discusses the evolving landscape of WebAssembly on the backend, running Java workloads on GPUs using TornadoVM, and optimizing distributed AI inference using llm-d and vLLM on Kubernetes. Edoardo explains how llm-d manages cache locality (KV and prefix caches), request routing, and batch inference across Kubernetes clusters to maximize expensive GPU utilization.
Key Takeaways
- Wasm has matured into a backend runtime for sandboxing, cross-language compilation, and workload migration between browsers and end-user devices.
- TornadoVM allows developers to compile and run Java code directly on GPU backends, enabling projects like GPU-accelerated Llama 3 written entirely in Java.
- While vLLM optimizes high-throughput inference on a single instance via PagedAttention, llm-d extends this across Kubernetes clusters to manage multi-node distributed inference.
- Traditional Kubernetes load balancers break LLM efficiency; llm-d balances staying with the same instance to leverage cached conversational context while preventing node overload.
- llm-d introduces batch inference during idle cluster periods and semantic classification to route prompts to right-sized, cost-effective models without sacrificing privacy.
