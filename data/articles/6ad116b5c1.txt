Dozens of MSP ScreenConnect servers have been targeted in a month-long campaign exploiting a vulnerability patched in September, cybersecurity firm Huntress reports.
The attacks, ongoing since at least October 20, aim to exploit CVE-2026-84869 (CVSS score of 9.9), a critical missing authorization and improper privilege management
ConnectWise patched the security defect on September 8, and CISA added it to the KEV catalog on September 11. Huntress warned at the time that exploitation started on August 20.
Now, the cybersecurity firm says a new wave of attacks is targeting ScreenConnect instances, with a focus on managed service provider (MSP) servers.
The hackers exploit CVE-2026-84869 via requests to run a guest-pushed batch file that connects to a Telegram bot and installs a rogue ScreenConnect client.
“Attackers appear to be spraying servers blindly: Since October 20, we’ve seen at least 688,000 guest ‘run file’ requests for update*.bat hit 42 MSP ScreenConnect servers from 29 IP addresses, waiting for any technician to join,” Huntress says.
According to the cybersecurity firm, the activity is different from the recently observed campaigns targeting ScreenConnect instances with the SCKit malware toolkit and with unauthorized sessions from machines posing as crypto exchanges.
The exploitation of CVE-2026-84869, it explains, allows attackers to push malicious files to technicians’ machines and get their own clients to execute them when the technician joins the session. The technician sees no prompt when the files are executed.
“An MSP technician’s workstation typically holds RMM consoles, saved credentials, and access to every customer, making it an exceptionally attractive target. When a technician joins a remote session, their ScreenConnect host client and the guest machine can exchange files,” Huntress notes.
In one attack, a rogue ScreenConnect client disguised as Windows Update was installed and spawned within nine seconds of the host client running the guest-pushed bat file.
As part of another, the guest machine pushed a text file two seconds after the technician joined the session, and the technician’s client ran the file three seconds later.
In October, a targeted attack hit an MSP server: the attacker joined as a guest in three real sessions the technician had created and asked the client to execute a file designed to drop a script into the technician’s computer’s Startup folder.
Organizations should update technicians’ ScreenConnect host clients to version 26.6.5 or later, along with all the Access agents ConnectWise lists.
