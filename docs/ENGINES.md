# Смена «движка»: Claude, ChatGPT или другая модель

> Готовые пошаговые инструкции для агентов: `docs/SWITCH-TO-CODEX.md` (передать роль Codex) и `docs/SWITCH-TO-CLAUDE.md` (вернуть Claude). Ниже объяснение, как это устроено и почему.

## 1. Что стоит за проектом (простая модель)
В проекте четыре слоя. Нейросеть нужна только в одном.

| Слой | Что делает | Кто делает | Зависит от Claude? |
|---|---|---|---|
| 1. Сбор | Читает RSS изданий, оставляет свежее и доверенное → `data/candidates.json` | GitHub Actions (`collect.yml`, `scripts/collect.py`) | Нет |
| 2. Редактор | Выбирает главное, оценивает важность, пишет русские пересказы, сверяет издания → `data/digest.json` | **Облачная задача Claude** | **Да, это единственное** |
| 3. Выпуск | Проверяет JSON, рисует страницу, публикует, шлёт в Telegram | GitHub Actions (`validate.py`, `render.py`, `notify.py`) | Нет |
| 4. Контроль и доставка | Сообщение о сбое | `check.yml` | Нет |

Поэтому «сменить движок» значит поменять только слой 2: кто-то другой читает те же заголовки по тем же правилам и кладёт `digest.json` в то же место. Слои 1, 3, 4 не меняются.

Связующее звено: формат `digest.json` (см. `docs/ARCHITECTURE.md`) и правила в `routine_prompt.md`. Всё, что соблюдает их, будет опубликовано. Страница не знает, кто написал дайджест.

## 2. Что значит «в один клик» (честно)
Полностью автоматически без вашего участия другая модель сможет работать только если у неё есть (а) расписание и (б) право записи в репозиторий, и (в) это входит в подписку. У Claude есть всё три (облачная задача). У ChatGPT по подписке, по моим данным, есть расписание (Tasks) и облачный Codex, но я не смог открыть их страницы и не знаю точно, умеют ли они по расписанию писать в GitHub. Это нужно проверить (раздел 5). Поэтому сегодня реально предлагаю три уровня.

| Уровень | Что делаете | Время | Платно? |
|---|---|---|---|
| A. Вручную с телефона | 4 действия (раздел 3) | 2–3 минуты в день | Нет (подписка ChatGPT) |
| B. Расписание в ChatGPT/Codex | Нужно проверить возможности (раздел 5) | один раз настроить | Скорее по подписке, проверить |
| C. Автоматически через API | Новый шаг в Actions с ключом модели | один раз настроить | Токены платные; у некоторых сервисов есть бесплатный лимит, не проверено |

## 3. Уровень A: ChatGPT вручную (работает уже сейчас)
Каждую ночь в 05:00 (Варшава) Actions пишет файл `handoff/PROMPT-FOR-OTHER-AI.md`: готовый запрос с правилами и сегодняшними заголовками (около 60 КБ). Это тот же промпт, что у Claude, только без команд git.

1. Откройте на GitHub (в браузере или приложении) файл `handoff/PROMPT-FOR-OTHER-AI.md`, нажмите **Raw** и скопируйте весь текст (на телефоне: выделить всё → копировать). Зачем: ИИ в чате не видит ваш репозиторий, ему нужно передать и правила, и данные одним куском.
2. Вставьте в новый чат ChatGPT. Лучше выбрать модель, умеющую «думать» (Thinking), она точнее следует правилам. Зачем: здесь мы просим не болтать, а вернуть строго JSON.
3. Дождитесь ответа: один JSON-объект. Нажмите «Копировать» у блока.
4. GitHub → `data/digest.json` → значок карандаша → выделить всё, вставить → **Commit changes**. Зачем: любой коммит с изменением `data/digest.json` запускает `publish.yml`.
5. Что произойдёт: `validate.py` проверит JSON и ссылки. Если ChatGPT испортил формат или придумал ссылку, публикация остановится с понятным сообщением, и в 07:15 `check.yml` напомнит. Если всё хорошо, придёт сообщение в Telegram.

Перед этим отключите облачную задачу Claude (claude.ai/code/routines → задача → пауза/выключить), иначе в 06:12 она перезапишет ваш файл. Включить обратно можно в любой момент: расписание и промпт сохраняются.

## 4. Как сравнить Claude и ChatGPT, не ломая рабочий дайджест
Не коммитьте ответ ChatGPT в `data/digest.json`: он сразу уйдёт в Telegram. Для эксперимента:
1. Сохраните ответ в `data/experiments/chatgpt-ДАТА.json` (папку создайте сами). Для Claude сохраните копию рабочего `data/digest.json` как `data/experiments/claude-ДАТА.json` (`git show HEAD:data/digest.json > ...`).
2. VS Code → Terminal → Run Task → «Digest: сравнить дайджест другой модели» → укажите путь. Проверка покажет ошибки формата, а в папке `out/` появится `preview-ИМЯ.html`. Открывайте два файла в Chrome рядом (режим телефона 393 px). Фото в предпросмотре без сети не грузятся, сравнивайте тексты и порядок.
3. Что сравнивать:
   - выбор: самое ли главное попало, нет ли мусора и курьёзов в серьёзных темах;
   - пересказы: нет ли придуманных деталей (сверяйте с заголовками), понятен ли русский, нет ли оценочных слов в политике;
   - достоверность: у каждой политической новости два издания или оговорка;
   - важность: разумно ли расставлены тройки (не больше 7);
   - дисциплина формата: сколько ошибок нашёл `validate.py`;
   - стоимость и скорость: сколько своего лимита потратили.
4. Победитель идёт в рабочую схему. Запись «кто лучше» заносите в `docs/DECISIONS.md`.

## 5. Что проверить про ChatGPT/Codex, прежде чем строить уровень B
Из поиска видно, что у ChatGPT есть запланированные задачи (Tasks) и что у Codex есть автоматизации по расписанию. Страницы OpenAI с условиями я открыть не смог, поэтому ничего не утверждаю. Спросите у себя или у ChatGPT и проверьте в справке OpenAI:
- входят ли Tasks/автоматизации Codex в ваш тариф и сколько можно активных;
- может ли задача сама открыть репозиторий `skeptplik/daily-digest`, прочитать `handoff/PROMPT-FOR-OTHER-AI.md` и записать `data/digest.json` (напрямую в `main` либо через pull request);
- если только через pull request: тогда нужно решить, кто его объединяет (можно автоматическим правилом GitHub после успешной проверки `validate.py`; я могу это добавить);
- доступ в интернет у задачи и запрашивает ли она подтверждения (у Claude именно это ломало поиск по сайтам, см. `docs/STATUS.md`, тест B).
Если ответы «да», уровень B сводится к тому, чтобы вставить в задачу ChatGPT текст «открой файл handoff/…, выполни, запиши результат в data/digest.json». Остальное уже готово.

## 6. Уровень C (если решите платить или найдёте бесплатный лимит)
Нужен новый шаг в Actions после `collect.yml`: скрипт отправляет содержимое `handoff/PROMPT-FOR-OTHER-AI.md` в API выбранной модели, получает JSON, пишет `data/digest.json`. Ключ хранится как секрет GitHub. Потребуется выбрать провайдера и проверить текущие условия его бесплатного тарифа. Скажите, если нужно, и я сделаю.

## 7. Где лежит «переключатель»
- Кто пишет дайджест сегодня: включённая облачная задача Claude (claude.ai/code/routines). Чтобы переключиться на другого, её нужно поставить на паузу, а новый источник должен писать только `data/digest.json`.
- Правила отбора: `routine_prompt.md`. Запрос для других моделей строится из него автоматически (`scripts/make_handoff.py`), поэтому достаточно править один файл. После правки обновите текст в самой задаче Claude (она читает свой, внутренний).
- Защита от чужих ошибок: `scripts/validate.py` в `publish.yml` (непрошедший файл не публикуется) и сверка сайта в `check.yml`.

## 8. Чат «Утренний дайджест» в Claude: нужен ли он
Эти чаты — журнал запусков: каждый запуск по расписанию открывает отдельную сессию, где видны действия и итоговый ответ («собрано N новостей…»). Для работы дайджеста они не нужны: расписание и промпт живут в самой задаче, а не в чате.
- Не удаляйте саму задачу в разделе routines: это и есть «движок».
- Отдельные чаты запусков можно удалять. Пока схема не устоялась (1–2 недели), оставляйте последние: по итоговому ответу видно, что случилось, если что-то пойдёт не так.
- Стабильно работает: храните последние несколько и удаляйте старые, чтобы не мешали.
- Чат, где мы всё настраивали (этот), содержит историю решений. Её главное мы вынесли в `docs/`, так что для работы он больше не нужен. Но он может пригодиться как справка, если захотите вспомнить, почему сделано так или иначе.
