# Runbook: передать роль редактора дайджеста Codex (ChatGPT)

Как пользоваться: откройте Codex в папке проекта и напишите: «Открой docs/SWITCH-TO-CODEX.md и выполни по шагам, останавливайся там, где нужно моё действие». Всё остальное агент делает сам.

Для чего: сейчас `data/digest.json` каждое утро пишет облачная задача Claude. Здесь описано, как поручить это Codex, не ломая остальную цепочку (сбор заголовков, публикация, Telegram, проверка сбоя, задача Windows работают от самого файла `data/digest.json` и от GitHub, а не от модели).

Одновременно должен работать ОДИН редактор. Два записывают в один файл, последний пуш перетирает предыдущий и в Telegram приходят дубли.

## Для агента (Codex): порядок действий

### Шаг 0. Честная проверка возможностей (до любых изменений)
Ответьте владельцу по-русски, что вы реально умеете, не угадывая:
1. Есть ли у вас автоматизации/запланированные запуски и можно ли поставить ежедневный запуск на 06:12 по Europe/Warsaw (в Варшаве зима UTC+1, летом UTC+2: нужно именно местное время)?
2. Выполняется ли такой запуск без человека (когда компьютер выключен, в облаке, или только пока приложение открыто на ПК)? Это критично: цель — работа при выключенном компьютере.
3. Можете ли вы в таком запуске выполнить `git push origin main` без запроса подтверждения?
4. Нужен ли вам интернет (не нужен: сырьё лежит в `data/candidates.json`).
Если на вопрос 1, 2 или 3 ответ «нет» или «не знаю»: ОСТАНОВИТЕСЬ. Скажите владельцу, что полностью автоматический режим невозможен, и предложите ручной вариант из `docs/ENGINES.md`, раздел 3. Ничего не меняйте.

### Шаг 1. Состояние репозитория
`git fetch origin main && git checkout main && git pull`. Прочитайте `AGENTS.md`, `docs/STATUS.md`, `docs/OPERATIONS.md`, `routine_prompt.md`, `data/engine.json`. Если `engine` уже `codex`, сообщите и остановитесь.

### Шаг 2. Пробный прогон без публикации
1. Прочитайте `data/candidates.json` и `routine_prompt.md`. Выполните его пункты 1–5 (отбор, формат, проверка). Первую строку про репозиторий и пункт 0 пропустите, интернет не используйте.
2. Запишите результат В `data/experiments/codex-ГГГГ-ММ-ДД.json`, НЕ в `data/digest.json` (иначе он уйдёт в Telegram).
3. `python scripts/validate.py data/experiments/codex-ГГГГ-ММ-ДД.json` — должно быть 0 ошибок.
4. `DIGEST_FILE=data/experiments/codex-....json NO_NETWORK=1 PLACEHOLDER_IMAGES=1 python scripts/render.py` (на Windows через `set`) — получите `out/preview-codex-....html`.
5. Покажите владельцу краткую сводку (сколько новостей, важных, темы) и попросите открыть предпросмотр. Если у владельца есть дайджест Claude за тот же день, предложите сравнение (критерии в `docs/ENGINES.md`, раздел 4).
6. Продолжайте, только если владелец сказал «переключаем».

### Шаг 3. Поставить Claude на паузу (действие владельца, вы только просите)
Скажите владельцу: «Откройте claude.ai/code/routines → задача «Утренний дайджест» → поставьте на паузу (выключите переключатель расписания). Не удаляйте её. Напишите мне, когда сделано». Дождитесь подтверждения.

### Шаг 4. Создать ежедневную автоматизацию в Codex
Параметры:
- Имя: «Утренний дайджест».
- Расписание: каждый день 06:12, часовой пояс Europe/Warsaw. Это через 3 часа после сбора заголовков (03:00 UTC); не ставьте раньше 05:30 по Варшаве.
- Рабочая папка/репозиторий: `skeptplik/daily-digest`, ветка `main`.
- Разрешения: чтение репозитория, запуск `git` и `python`, запись файлов, `git push origin main`. Сеть не нужна.
- Текст запроса автоматизации (вставить дословно):

```
Репозиторий skeptplik/daily-digest, ветка main. Ты редактор ежедневного дайджеста. Выполни: git fetch origin main && git checkout -B main origin/main. Затем открой routine_prompt.md и выполни его пункты 1-6 полностью. Первую строку про репозиторий и пункт 0 пропусти. Интернет не используй: все заголовки лежат в data/candidates.json. Результат data/digest.json обязан пройти python scripts/validate.py без ошибок. Закоммить (сообщение «Дайджест за ДАТА») и запушь в main. Если push невозможен, не пиши в другие ветки молча: сообщи об этом в итоге. В конце коротко отчитайся: сколько новостей, сколько важных, у каких новостей политики один источник.
```

### Шаг 5. Зафиксировать переключение
1. В `data/engine.json` поставьте `"engine": "codex"` и `"since"` на сегодняшнюю дату.
2. В `docs/STATUS.md` добавьте строку: «ДАТА: редактор переключён на Codex, автоматизация создана (где и как запускается)».
3. Закоммитьте («Движок дайджеста: Codex») и запушьте. Изменение только этих файлов рассылку не запускает.

### Шаг 6. Тестовый запуск
Запустите автоматизацию вручную один раз. Проверьте: в `main` появился коммит «Дайджест за ДАТА»; `publish.yml` в Actions зелёный (`validate.py` пропустил); владельцу пришло сообщение в Telegram со ссылкой. Если что-то красное, скажите, на каком шаге, и предложите откат (ниже).

### Откат
Скажите владельцу выполнить `docs/SWITCH-TO-CLAUDE.md`.

## Что остаётся неизменным при переключении
`collect.yml` (03:00 UTC), `publish.yml`, `check.yml` (06:15 UTC), `notify.py`, задача Windows. Сообщение о сбое после переключения называет активный движок (по `data/engine.json`).
